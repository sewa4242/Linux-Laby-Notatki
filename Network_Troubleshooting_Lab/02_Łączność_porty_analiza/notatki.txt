### Podstawowe pojęcia komendy ss ###
PORT        To punkt komunikacji który pozwala systemowi przekazać ruch siecowy do konkretnej aplikacji
LISTEN	serwer czeka
SYN_SENT	próbujemy się połączyć
SYN_RECV	ktoś próbuje się połączyć
ESTABLISHED	połączenie zestawione
FIN_WAIT	zamykanie
TIME_WAIT	czekanie po zamknięciu

### Sprawdzanie co nasłuchuje na serwerze ###

Flaga -p w komendzie ss wymaga uprawnień root, aby wyświetlić proces powiązany z gniazdem.
Bez sudo kolumna Process pozostaje pusta.

### LISTEN VS ESTABLISHED ###

ESTAB              0                   0                                [::ffff:192.168.50.80]:ssh                            [::ffff:192.168.50.203]:49336               users:(("sshd",pid=1461,fd=4),("sshd",pid=1386,fd=4))

1.Port serwerowy to ssh zazwyczaj cyfry dla ssh to 22 
2.Klient to 49336 --- port ephermal zawsze wysokie liczby 
3. Port klienta (ephermal ) jest wysoki dlatego iż jeden port serwerowy może nawiązać połączenie wiele razy stąd wysoka liczba portu klienta, każde nowe połączenie na porcie serwerowym = nowa liczba portu klienta 

Połączenie TCP = para:
(local_ip:local_port) ↔ (remote_ip:remote_port)

sshd (LISTEN) → proces główny
sshd (ESTABLISHED) → proces potomny obsługujący sesję

Model: daemon + fork per connection
Serwer działa jako daemon, który nasłuchuje na porcie.
Po nawiązaniu połączenia tworzy osobny proces do obsługi klienta.

### Recive-Q / Send-Q ###
	#STAN ESTABLISHED
	Recv-Q to liczba bajtów, które przyszły do mojego hosta i czekają aż program je odczyta.
Czyli: 
-dane przyszły z sieci
-leżą w buforze
-proces jeszcze ich nie przeczytał
#TO ROZMIAR BUFORA
	Send-Q to liczba bajtów, które mój host chce wysłać do drugiej strony, ale jeszcze nie zostały wysłane lub potwierdzone.
Czyli:
- dane wysłane
- Czekają na potwierdzenie TCP 
#TO DANE W KOLEJCE
	#STAN LISTEN
	Recv-Q  --- aktaulna liczba oczekujących połączeń 
	Send-Q  --- maksymalny rozmiar backlog (limit) 

Backlog to: Kolejka oczekujących połączeń TCP.  Które zostały już zainicjowane ale jeszcze nie zostały odebrane przez aplikację.

	Np. LISTEN 0 511 *:http  0 --> aktualnie nikt nie czeka w kolejce  511 --> maksymalnie 511 połączeń może czekać 
ZAPAMIĘTAĆ!!
Recv-Q → aplikacja lokalna nie czyta danych wystarczająco szybko	Wysokie Recv-Q → problem aplikacyjny / przeciążenie CPU / blokada I/O
Send-Q → druga strona nie potwierdza danych wystarczająco szybko	Wysokie Send-Q → problem sieciowy / druga strona wolna / brak ACK
